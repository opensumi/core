# feat/0710 对比 main 的行为验收用例

## 对比基线

- 验收分支：`feat/0710`
- 对比分支：`main`
- 验收快照：`eb36968e371999ca1dc294bdbc8d9087a8799b4c`
- Merge Base：`094b998ee11d130821ea25af4390e656e35ea425`
- 对比范围：`main...HEAD` 中的产品代码和测试代码；不包含本地未提交的文档与临时文件。
- 本清单用于人工验收。仓库内已有自动化场景仍以对应 `.scenario.md`、Jest 和 Playwright 用例为准。

## 主要行为变化

1. 编辑器新增固定标签能力，包括固定区域、关闭保护、滚动可达性、持久化和 VS Code Tab API 状态同步。
2. Agentic 布局新增常驻任务工作台，包括项目管理、任务创建、跨项目会话激活、项目名称、归档和尺寸调整。
3. ACP Chat 新增排队任务，包括严格 FIFO、行内编辑、暂停/继续、立即发送、失败恢复和会话隔离。
4. ACP 输入补充快捷键、焦点、粘贴、图片和展开行为；工具调用卡片补充键盘和无障碍交互。
5. ACP 会话补充启动预热、进程池容量保护、浏览器断开后重连、流式会话恢复、显式取消和失败资源清理。
6. Agentic 布局补充最大化、窄屏自动收起、会话切换加载态，并升级弹窗、通知和终端上下文生命周期。

## 验收环境与数据

- 使用一次性工作区，至少包含 `editor.js`、`editor2.js`、`editor3.js`。
- 默认布局用例使用 `default` profile；Agentic 任务和排队任务使用 `interactive` profile。
- Agentic 用例建议使用 `test/bdd/fixtures/acp-agent/mock-acp-agent.mjs` 的确定性 fixture，避免依赖真实模型输出。
- 流式恢复用例使用 `--fixture=long-stream`；历史恢复使用 `--fixture=history`；错误恢复分别使用 `--fixture=create-failure`、`--fixture=send-failure` 和 `--fixture=load-failure`。
- 进程池用例将 `ai.native.acp.threadPoolSize` 设为 3；容量竞态和失败注入优先执行 node-contract，不依赖真实模型。
- 跨项目用例准备三个目录：当前项目、另一个存在的项目、一个已删除或不可访问的项目。
- 验收期间不要断言 Agent 回复正文、思考内容、工具参数或精确流式时序。
- 启动服务前可检查端口：

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN || true
lsof -nP -iTCP:8000 -sTCP:LISTEN || true
```

## A. 编辑器固定标签

### A-01 固定非当前标签不切换编辑器

- 优先级：P0
- 前置：依次打开 `editor.js`、`editor2.js`，当前标签为 `editor2.js`。
- 操作：右键非当前的 `editor.js`，选择“固定标签”。
- 预期：
  - `editor.js` 移到固定区域并显示“取消固定”控件。
  - 当前编辑器仍是 `editor2.js`，编辑器焦点不被抢走。
  - `editor.js` 不再是预览标签。
- 自动化参考：`test/bdd/editor-pinned-tabs.scenario.md` Part A。

### A-02 固定标签的关闭保护

- 优先级：P0
- 前置：`editor.js` 已固定，另有至少一个普通标签。
- 操作：依次尝试关闭按钮、中键点击、`Cmd/Ctrl+W`、“关闭其他”、“关闭右侧”、“关闭全部”和“关闭已保存”。
- 预期：
  - 固定标签不显示普通关闭按钮，中键不能关闭。
  - 批量关闭操作跳过所有固定标签。
  - 当 `Cmd/Ctrl+W` 作用于固定标签时，切换到第一个普通标签而不关闭固定标签。
  - 若组内只有固定标签，`Cmd/Ctrl+W` 不执行关闭，也不把焦点切到其他编辑器组。

### A-03 显式关闭与重新打开

- 优先级：P0
- 前置：`editor.js` 已固定并已保存。
- 操作：从标签右键菜单选择“关闭”，随后执行“重新打开已关闭的编辑器”。
- 预期：
  - 显式“关闭”可以关闭固定标签。
  - 重新打开后，`editor.js` 是普通标签，不自动恢复固定状态或原固定位置。

### A-04 取消固定快捷键与键盘按钮

- 优先级：P0
- 前置：`editor.js` 已固定。
- 操作：分别使用“取消固定”按钮的 Enter、Space，以及 `Cmd/Ctrl+K` 后按 `Shift+Enter`。
- 预期：
  - 三种方式都能取消固定。
  - 操作按钮时不会触发父标签切换。
  - 取消固定后显示普通关闭按钮，且不会恢复为预览标签。

### A-05 固定标签的脏状态

- 优先级：P0
- 前置：`editor.js` 已固定。
- 操作：观察已保存状态，然后编辑文件但不保存。
- 预期：
  - 已保存时不显示虚假的脏状态圆点。
  - 未保存时同时显示脏状态和“取消固定”控件。
  - 保存后脏状态消失，固定状态保持不变。

### A-06 非换行模式下固定区域保持可见

- 优先级：P1
- 前置：`editor.wrapTab=false`，固定至少两个标签，再打开多个普通标签。
- 操作：水平滚动普通标签区域到最右侧。
- 预期：
  - 固定区域保持在左侧，不随普通标签一起滚走。
  - 编辑器操作区和右侧扩展内容不被覆盖。
  - 当前普通标签在固定区域右侧仍有可见像素并可操作。

### A-07 固定标签过宽时仍可到达当前标签

- 优先级：P1
- 前置：固定足够多的标签，使固定区域宽度超过可用宽度。
- 操作：通过资源树、快捷键或其他非直接点击方式激活最右侧固定标签。
- 预期：
  - 固定区域形成独立的横向滚动视口。
  - 当前固定标签会滚动到固定区域和外层视口的可见范围内。
  - 不会把普通标签区永久挤到完全不可用。

### A-08 标签换行模式与动态切换

- 优先级：P1
- 前置：固定两个标签，保留一个普通标签。
- 操作：先设置 `editor.wrapTab=true`，再运行时切回 `false`。
- 预期：
  - 换行模式下只有一个自然换行的标签序列，顺序为固定标签在前、普通标签在后。
  - 不出现单独的固定标签行或固定区域横向滚动条。
  - 切回非换行模式后，固定区域宽度和当前标签可达性重新计算正确。

### A-09 固定状态持久化

- 优先级：P0
- 前置：固定 `editor.js`，等待编辑器状态保存。
- 操作：刷新页面或重启 IDE。
- 预期：
  - `editor.js` 恢复为固定标签。
  - 缺失、无法恢复或不支持恢复的资源不会导致后续普通标签被误固定。
  - 同一个 URI 在不同编辑器组中的固定状态相互独立。

### A-10 拖拽、拆分与跨组行为

- 优先级：P1
- 前置：准备两个编辑器组，并包含固定、普通和预览标签。
- 操作：
  1. 将普通标签拖入固定区域。
  2. 将固定标签拖到普通区域。
  3. 将固定标签拆分到新组。
  4. 将固定标签拖入空的新组。
- 预期：
  - 拖入固定区域后变为固定；拖出后变为普通。
  - 预览标签拖入固定区域时先转为正式标签。
  - 拆分后的新组副本保持固定，源组固定状态不变。
  - 拖入空组时保留源标签的固定状态。

### A-11 扩展 Tab API 同步

- 优先级：P1
- 前置：安装或运行能够读取 VS Code Tab API 的测试扩展。
- 操作：固定、取消固定并移动标签。
- 预期：
  - 扩展侧 `Tab.isPinned` 与界面状态一致。
  - 固定或取消固定导致排序变化时，扩展侧顺序同步更新。
  - 仅固定边界变化但索引不变时，扩展仍收到状态更新。

## B. Agentic 任务工作台

### B-01 Agentic 工作台基本布局

- 优先级：P0
- 前置：以 Agentic 布局打开 IDE。
- 操作：显示 AI Chat。
- 预期：
  - 左侧区域标题为 `Agent Tasks`，任务列表、主对话区、资源管理器和编辑器同时可见。
  - 任务列表位于 ACP Chat 槽位内部，不覆盖编辑器或资源管理器。
  - 行样式接近 OpenSumi 原生树/列表，不出现卡片式任务行、渐变栏或永久文字操作按钮。
- 自动化参考：`tools/playwright/src/tests/acp-chat-agentic-task-workbench.test.ts`。

### B-02 任务列表尺寸调整

- 优先级：P1
- 前置：任务列表可见。
- 操作：分别用鼠标拖拽和键盘调整宽度，再缩窄整个 Chat 槽位。
- 预期：
  - 默认宽度约为 244px，最小宽度为 208px。
  - 最大宽度为 `min(280px, Chat 槽位宽度 - 360px)`。
  - 主对话区始终保留至少 360px。
  - 调整结果保存在当前浏览器标签页；页面刷新后恢复用户宽度。
  - Chat 槽位变窄后，之前保存的过宽值会被安全收敛；重新变宽后恢复用户原先偏好的宽度，但不超过 280px。
  - 指针离开窄调整手柄后，拖拽仍连续生效；焦点样式清晰。

### B-03 项目显示名称与完整路径

- 优先级：P0
- 前置：准备无自定义名称的项目，以及末级目录同名的两个可用项目。
- 操作：观察项目列表、搜索前后标签和悬停提示。
- 预期：
  - 默认显示规范化 cwd 的最后一段；文件系统根目录显示 `/`。
  - 同名项目使用最短父路径后缀消歧。
  - 搜索任务不会改变项目标签或项目/任务顺序。
  - 悬停项目名称可看到完整 cwd。

### B-04 重命名项目

- 优先级：P1
- 前置：存在可用的活动项目。
- 操作：从项目管理菜单打开重命名弹窗，分别执行保存、取消、清空名称。
- 预期：
  - 输入框自动聚焦；未命名项目以默认名称作为占位符，并单独展示完整 cwd。
  - 保存会去除首尾空格并持久化非空名称。
  - 取消不修改名称。
  - 清空后恢复派生默认名称。
  - 重命名不改变项目身份、任务归属、ACP 会话或排序；归档项目不可重命名。

### B-05 添加项目但不切换 IDE 工作区

- 优先级：P0
- 前置：当前编辑器和资源树已打开一个工作区。
- 操作：点击任务列表标题栏的“添加项目”，选择另一个目录。
- 预期：
  - 使用现有目录选择器。
  - 新目录作为空项目组出现，但浏览器 URL、资源树和编辑器工作区不变化。
  - 重复选择已有目录只重新校验可用性，不创建重复项目。
  - 标题栏“添加项目”只添加项目，不创建任务。

### B-06 项目组内创建任务

- 优先级：P0
- 前置：项目组可见且至少配置一个 ACP Agent。
- 操作：点击项目组标题中的图标 `+`，输入第一条内容并发送。
- 预期：
  - 项目组只有一个图标式新建任务按钮，不显示“New Task”文字或 Agent 下拉箭头。
  - 草稿使用该项目记忆的 Agent 和该项目 cwd。
  - 发送第一条内容前不创建持久任务行；首次发送成功后才出现任务行。
  - 不切换 IDE 工作区、不刷新页面，也不触发脏编辑器保存/丢弃提示。

### B-07 对话标题栏创建任务与 Agent 选择

- 优先级：P0
- 前置：配置 `Agent A`、`Agent B`。
- 操作：分别点击标题栏主 `+` 和相邻的 Agent 下拉按钮，再发送首条内容。
- 预期：
  - 主 `+` 使用当前项目记忆的 Agent 直接打开任务草稿，不打开菜单。
  - 相邻 Agent 下拉按钮点击后才打开锚定菜单，悬停不会打开；菜单不出现“选择项目”。
  - 菜单包含 Agent 列表、下一任务将使用的 Agent 勾选状态和“Agent 配置”；选择 Agent 后立即打开对应草稿。
  - 已选中持久任务时，新草稿沿用该任务所属项目；否则使用当前 IDE 工作区。
  - Agent 选择只更新目标项目的 Agent 记忆，不修改用户级默认 Agent。
  - 无可用 Agent 时主 `+` 禁用并给出原因，Agent 下拉仍可打开“Agent 配置”，项目组 `+` 禁用并给出原因。

### B-08 当前项目任务激活

- 优先级：P0
- 前置：当前项目有两个可恢复任务，其中一个带未读标记。
- 操作：点击非当前任务。
- 预期：
  - 对应 ACP 会话被恢复，选中态移动到目标任务。
  - 激活成功后才清除未读标记。
  - URL、IDE 工作区、资源树和编辑器状态不变化。

### B-09 跨项目任务原地激活

- 优先级：P0
- 前置：当前工作区有未保存编辑器；另一个项目有可恢复任务。
- 操作：点击另一个项目的任务。
- 预期：
  - 仅切换 ACP Active Session，不切换 IDE 工作区。
  - URL、资源树、编辑器内容和未保存状态保持不变。
  - 不显示保存/丢弃/取消工作区切换弹窗。
  - 标题栏显示“Agent 工作目录”及目标项目名称，悬停显示完整 cwd。
  - 激活成功后才清除目标任务未读标记。

### B-10 激活失败与快速连续选择

- 优先级：P0
- 前置：准备一个无法恢复的任务和两个可恢复任务。
- 操作：
  1. 先点击无法恢复的任务。
  2. 快速连续点击两个可恢复任务，并人为让前一次请求更晚返回。
- 预期：
  - 激活失败时保留原对话、原任务选中态和未读标记，不打开无绑定草稿。
  - 快速选择遵循“最后一次选择生效”，旧请求晚返回不能覆盖最新选择。

### B-11 不可用项目过滤

- 优先级：P0
- 前置：注册表保留一个 cwd 已不存在的项目及其任务。
- 操作：观察活动区、归档区、搜索结果和注意力计数。
- 预期：
  - 不可用项目及其任务默认全部隐藏。
  - 不贡献可见任务数或注意力计数。
  - 不显示项目组新建按钮，也不会调用工作区打开逻辑。
  - 数据仍保留在注册表中，目录恢复后可重新校验。

### B-12 搜索、状态与注意力

- 优先级：P1
- 前置：存在运行中、就绪、停止、错误、需要权限和需要输入的任务。
- 操作：按任务标题搜索并观察各任务行。
- 预期：
  - 只按不可变任务标题过滤，不搜索提示词或消息内容。
  - 搜索不改变项目和任务原始顺序。
  - `ready` 任务不显示冗余状态文字；运行中、停止和错误任务显示语义图标与可见状态文字。
  - 权限或输入注意力状态优先于普通运行状态，并替换普通状态展示；未读圆点仍独立保留。
  - 任务行保持单行，完整标题仍可通过悬停或无障碍信息访问。

### B-13 归档与恢复

- 优先级：P0
- 前置：准备就绪、停止、错误和运行中任务。
- 操作：悬停或键盘聚焦任务行，执行归档；展开“已归档任务”并恢复。
- 预期：
  - 只有就绪、停止或错误任务可以归档；运行中任务不可归档。
  - 归档/恢复是图标操作，默认不长期显示文字按钮，但具有明确的无障碍名称。
  - 恢复后任务回到原项目，标题、状态、项目引用和会话身份不丢失。

### B-14 Agentic 与 Classic 边界

- 优先级：P1
- 前置：Agentic 任务列表已有任务和归档状态。
- 操作：Agentic -> Classic -> Agentic。
- 预期：
  - Classic 保留原有 ACP 历史按钮/弹层行为，不显示 Agentic 任务工作台。
  - 回到 Agentic 后任务列表、标题栏新建任务入口和原任务身份恢复。
  - 不改变 IDE 通用布局生命周期。

### B-15 项目组折叠与搜索展开

- 优先级：P1
- 前置：至少两个非空项目组，其中一个已折叠。
- 操作：使用鼠标、Enter 和 Space 折叠/展开项目组；折叠后搜索组内任务，再清空搜索。
- 预期：
  - 项目名称和数量组成一个带 `aria-expanded` 的折叠按钮；项目组 `+` 与管理按钮是独立操作，不触发折叠。
  - 只隐藏当前项目的任务行，不影响其他项目；空项目不显示可交互折叠按钮。
  - 搜索期间匹配项目临时展开，清空搜索后恢复用户之前的折叠状态。
  - 搜索不会永久修改折叠选择，也不会改变项目或任务顺序。

### B-16 Agentic 对话最大化与恢复

- 优先级：P0
- 前置：Agentic 布局中任务列表、资源管理器和编辑器均可见。
- 操作：点击标题栏最大化，再点击恢复；期间打开一个前台编辑器文件。
- 预期：
  - 最大化只隐藏 Agentic 工作台区域，保留当前任务、会话、输入草稿和排队任务。
  - 恢复后资源管理器和编辑器重新出现，原编辑器和任务选中态不变。
  - 最大化/恢复按钮图标和无障碍名称同步变化。
  - 工作台隐藏时，用户主动打开前台编辑器会重新显示工作台；后台打开或打开失败不会强制显示。

### B-17 窄屏响应式收起

- 优先级：P1
- 前置：Agentic 工作台已处于显示状态。
- 操作：将浏览器视口缩窄到 980px 以下，再恢复到 980px 以上。
- 预期：
  - 窄屏时工作台临时收起，只保留可用的 Agentic Chat 主区域，不产生横向溢出或覆盖。
  - 恢复宽度后，工作台按缩窄前的用户可见性选择恢复。
  - 临时响应式收起不清除任务、编辑器、布局缓存或用户的最大化选择。

## C. ACP 排队任务与输入行为

### C-01 生成期间提交形成严格 FIFO

- 优先级：P0
- 前置：Active Session 正在生成。
- 操作：依次提交 `fifo-1`、`fifo-2`、`fifo-3`。
- 预期：
  - 三条内容按提交顺序进入排队列表，计数正确，首次入队自动展开。
  - 当前生成完成后，只取队首开始发送，每条恰好发送一次。
  - 自动推进顺序严格为 `fifo-1`、`fifo-2`、`fifo-3`。
  - 入队、展开、收起和自动推进都不抢走主输入框焦点。
- 自动化参考：`test/bdd/acp-chat-agentic-queued-turns.scenario.md`。

### C-02 编辑非队首任务不改变顺序

- 优先级：P0
- 前置：队列为 `fifo-1`、`fifo-2`、`fifo-3`。
- 操作：编辑第二条为 `fifo-2-edited` 并保存。
- 预期：
  - 编辑器获得焦点。
  - 条目 ID、索引和 FIFO 位置保持不变。
  - 第一条仍可正常先发送，编辑第二条不阻塞队首。
  - 保存完成后焦点回到主输入框。

### C-03 编辑队首时阻塞自动推进

- 优先级：P0
- 前置：队首正在行内编辑，当前生成即将完成。
- 操作：分别验证保存、取消和删除队首编辑。
- 预期：
  - 未处理编辑前，队首不会自动发送。
  - 保存后发送修改后的队首；取消后发送原内容；删除后发送下一条。
  - 同时只能编辑一条；点击其他条目的编辑不会丢弃当前未保存内容，而是聚焦当前编辑器。
  - 有未保存行内编辑时不能收起队列。

### C-04 手动停止后暂停并继续队列

- 优先级：P0
- 前置：使用 `long-stream`，当前生成中，队列包含 `resume-head`、`resume-tail`。
- 操作：点击“停止”，等待取消完成，再点击“继续队列”。
- 预期：
  - 点击停止后队列立即进入“已暂停/已停止”，不会自动推进。
  - 两条排队任务顺序不变，当前已开始的任务不重新入队。
  - “继续队列”只启动 `resume-head` 一次，并保留 `resume-tail` 为下一条。

### C-05 立即发送等待取消确认

- 优先级：P0
- 前置：当前生成中，队列为 `immediate-first`、`immediate-selected`、`immediate-last`。
- 操作：对第二条选择“立即发送”。
- 预期：
  - 系统先取消当前生成；取消确认前不会发送目标任务。
  - 等待期间相关立即发送动作禁用，避免重复取消或重复发送。
  - 取消确认后，`immediate-selected` 只发送一次。
  - 剩余顺序为 `immediate-first`、`immediate-last`，后续继续按 FIFO。
  - 焦点只在立即发送完成后回到主输入框。

### C-06 立即发送取消或启动失败恢复

- 优先级：P0
- 前置：分别注入取消失败和目标启动失败。
- 操作：选择队列中的非队首任务立即发送。
- 预期：
  - 取消失败时目标任务恢复到队首，外部生成真实状态不被伪造，队列暂停。
  - 取消成功但目标启动失败时，目标同样恢复到队首并暂停。
  - 目标内容、ID、编辑状态和剩余 FIFO 不丢失、不重复。

### C-07 普通启动失败可恢复

- 优先级：P0
- 前置：使用一次性 `acpBddQueuedTurnStartFailure=reject-once` fixture。
- 操作：提交 `start-failure-head`，失败后点击“继续队列”。
- 预期：
  - 首次失败不创建用户消息行、加载状态或停止按钮。
  - 原任务恢复为队首，显示“已暂停/启动失败”。
  - 再次继续无需刷新，发送同一条任务且没有重复行或顺序变化。

### C-08 Agent 出错和取消失败后的显式恢复

- 优先级：P1
- 前置：分别注入 Agent 已开始后报错、停止请求失败。
- 操作：观察队列并使用继续、编辑、删除、新普通提交或立即发送恢复。
- 预期：
  - 已开始后报错的活动任务不重新入队，剩余任务保留并暂停。
  - 停止失败时保持暂停，不自动重试，避免重复外部操作。
  - 错误以非阻塞方式显示规范化原因，不弹出阻塞模态框。

### C-09 Active Session 切换隔离

- 优先级：P0
- 前置：Session A 正在生成并有排队任务和行内编辑；Session B 可选。
- 操作：切换到 Session B，再切回 Session A。
- 预期：
  - Session B 不显示 Session A 的队列、编辑器或加载状态。
  - Session A 的旧完成回调不能在 Session B 启动旧任务，也不能抢焦点。
  - 切换期间消息区域显示带 `role=status` 的“Loading chat…”状态并标记 busy；主输入、发送/停止、模式和模型配置暂时禁用。
  - 切换完成后输入与配置恢复可用，不把会话切换误显示为 Agent 正在生成。
  - 主草稿不被意外清空；输入展开状态退出但不发生异常焦点跳转。
  - 切回 Session A 不恢复已经清除的旧队列。

### C-10 清空、删除和取回最后一条

- 优先级：P0
- 前置：队列包含多条内容，其中一条正在编辑。
- 操作：分别执行删除、全部清除，以及主输入为空时按 `ArrowUp`。
- 预期：
  - 删除只移除目标任务；删除队首后下一条可以继续处理。
  - 全部清除会清空队列、编辑状态、暂停状态和一次性快速发送状态，但不会伪造当前已确认活动发送的结束。
  - `ArrowUp` 只取回队尾一条，恢复可支持的文本、Mention、图片和命令字段，光标位于末尾并聚焦主输入。
  - 队列为空时，`ArrowUp` 回退到原有输入历史行为。

### C-11 主输入快捷键和 IME

- 优先级：P0
- 前置：主输入获得焦点。
- 操作：验证 Enter、Shift+Enter、`Cmd/Ctrl+Shift+Enter`、Escape 和中文输入法组合态。
- 预期：
  - 空闲时 Enter 立即发送；生成中 Enter 入队。
  - Shift+Enter 插入换行。
  - `Cmd/Ctrl+Shift+Enter` 执行立即发送。
  - Escape 优先关闭 Mention、Slash 等临时浮层；无浮层时才停止生成并暂停队列。
  - 输入法组合期间上述提交快捷键不会误发送。

### C-12 一次性空 Enter 快速发送

- 优先级：P1
- 前置：主输入刚把一条任务加入队列，输入框为空。
- 操作：立即再次按 Enter；然后修改主草稿后重复尝试。
- 预期：
  - 第一次空 Enter 只对队首执行一次“立即发送”。
  - 使用后状态失效，不能重复触发。
  - 用户真实修改草稿、切换会话、清空队列或其他影响队首的动作都会使该状态失效。

### C-13 行内编辑快捷键

- 优先级：P1
- 前置：打开某条排队任务的行内编辑器。
- 操作：验证 Enter、Shift+Enter、`Cmd/Ctrl+Shift+Enter`、Escape。
- 预期：
  - Enter 原位保存；Shift+Enter 插入换行。
  - `Cmd/Ctrl+Shift+Enter` 保存并立即发送同一条任务。
  - Escape 丢弃本次编辑副本并保留原任务。
  - 保存、取消、删除和立即发送完成后焦点回主输入框。

### C-14 文本、图片和混合粘贴

- 优先级：P1
- 前置：分别聚焦主输入和行内队列编辑器。
- 操作：粘贴纯文本、HTML 外观的 `text/plain`、单张图片、文本与多张图片混合内容，并注入一张图片上传失败。
- 预期：
  - 文本插入到粘贴发生时的光标位置，不被当作 HTML 执行。
  - 图片附加到当前编辑的同一草稿，不迁移到另一个输入框。
  - 混合粘贴保留文本和上传成功的图片，只报告失败图片数量。
  - 异步上传完成前后，文本插入位置稳定；原编辑器卸载后不会把延迟结果写入新编辑器。

### C-15 输入展开状态保持

- 优先级：P1
- 前置：输入中包含文本、Mention、图片、选区和光标位置。
- 操作：点击展开按钮，并使用 `Shift+Alt/Option+Escape` 来回切换。
- 预期：
  - 按钮和快捷键使用同一命令语义。
  - 展开/收起不重建草稿，文本、Mention、图片、光标、选区和焦点全部保留。
  - Active Session 切换时退出展开状态。

### C-16 空白、命令与重复提交边界

- 优先级：P0
- 前置：分别准备空闲、`awaiting_prompt` 和正在生成的 Active Session。
- 操作：提交纯空白、contenteditable 空标签、仅 Slash Command 的草稿，并在一次异步提交尚未完成时快速双击发送或连续按 Enter。
- 预期：
  - 纯空白和视觉空白标签不创建会话、用户消息或请求；仅命令草稿仍是有效提交。
  - 空闲或 `awaiting_prompt` 时直接发送，不进入排队列表；确实正在生成时才形成排队任务。
  - 同一草稿的并发重复提交只接受一次，不产生重复用户行、重复请求或重复队列项。
  - 提交等待期间用户新输入的文本、图片、Agent 或命令修改不会被旧提交完成后的清理覆盖。

## E. ACP 会话恢复与进程池可靠性

### E-01 流式生成期间刷新并恢复

- 优先级：P0
- 前置：使用 `long-stream` 启动一个仍在生成的 Agentic 任务，记录会话 ID 和已显示输出。
- 操作：刷新浏览器，等待 IDE 与 Agentic Chat 恢复，再观察后续输出并点击“停止”。
- 预期：
  - 恢复同一个任务和会话 ID，不新增空会话，也不重复用户消息或重新发送提示词。
  - 刷新前已显示的内容恢复，刷新后的新流式更新继续到达。
  - 状态仍为生成中并提供“停止”；停止可以取消同一个重连会话，输入随后恢复可用。
  - 不出现永久加载、重复流、幽灵任务或 MCP token 泄漏。

### E-02 浏览器断开、重连与显式取消

- 优先级：P0
- 前置：同一个容器级 ACP 服务上存在运行中的会话，可建立新的浏览器连接。
- 操作：断开原浏览器连接，在 Agent 继续生成时建立新连接并重新附着，随后取消请求。
- 预期：
  - 浏览器断开只释放该连接的监听器，不终止 Agent 进程、不取消正在运行的请求。
  - 新连接先得到完整快照，再按顺序收到竞态窗口和后续更新；每条更新只出现一次。
  - 重新附着不创建、加载替代会话或重发提示词。
  - 新连接的取消操作能到达原运行会话；重复取消或会话已不存在时保持幂等。

### E-03 启动预热不阻塞前台任务

- 优先级：P1
- 前置：启用 ACP，准备一个安全的默认 cwd，并可控制预热线程初始化完成时机。
- 操作：启动 IDE，同时快速创建前台任务；再用不同 cwd 制造与预热不兼容的前台请求。
- 预期：
  - 启动最多预热一个待命进程，不创建会话、不阻塞 IDE 启动，预热失败只记录日志。
  - 并发或重复预热不会创建重复进程；待命进程被前台任务占用后不会自动持续补满。
  - 前台会话优先于预热；不兼容时等待预热初始化安全结束后替换，不误报容量已满。
  - 任意时刻进程数不超过配置上限。

### E-04 容量已满时保护运行中任务

- 优先级：P0
- 前置：进程池上限为 3，三个会话分别处于运行中、等待权限、保留/加载中等不可回收状态。
- 操作：创建或加载第四个会话。
- 预期：
  - 不驱逐运行中、等待权限、预热、保留或加载中的线程，也不超过 3 个进程。
  - 快速返回可操作的本地化提示，说明并发任务达到上限并建议切换或停止现有任务后重试。
  - 新建页面退出加载态，输入仍可恢复操作，不暴露 LRU、命令参数、环境变量、Token 或 MCP Header。
  - 其他已有任务仍可选择和继续运行。

### E-05 LRU 回收后历史会话仍可继续

- 优先级：P0
- 前置：池中有三个可复用的 `awaiting_prompt` 会话，并标记一个最久未使用会话。
- 操作：创建第四个会话，再选择被回收的历史会话并发送新内容。
- 预期：
  - 创建第四个会话复用最久未使用的可复用线程，池大小保持不变。
  - 被回收会话仍保留在历史和任务列表中；重新选择时自动懒加载，不显示“No active session”。
  - 懒加载完成后正常发送一次，不丢失历史、不重复提示词、不影响其他工作会话。

### E-06 断线进程回收但持久会话保留

- 优先级：P1
- 前置：存在一个已断线但仍有持久历史的会话，进程池接近容量上限。
- 操作：创建其他会话占用该容量，再重新选择断线会话。
- 预期：
  - 断线进程实例、终端、权限路由、监听器和活动映射被释放，可供新会话使用。
  - 持久会话元数据和对话历史不被删除，仍可通过新进程重新加载。
  - 普通提示词失败但进程仍连接时，不被错误当作可回收断线进程。

### E-07 创建、加载失败后的资源清理

- 优先级：P1
- 前置：分别注入新会话创建失败、已取得 sessionId 后失败、加载失败和替换进程初始化失败。
- 操作：执行新建或恢复，然后再次创建一个正常会话。
- 预期：
  - 失败会话释放权限路由、状态监听、引用计数、内置 MCP 标记和会话终端。
  - 同一会话被多个浏览器所有者保留时，释放单个引用不会提前清理；最后一个引用释放后才统一清理会话资源。
  - 已连接且健康的进程在普通创建/加载失败后仍可复用；初始化失败的新替换进程被销毁。
  - 后续正常会话可成功创建，容量不被幽灵会话占用，也不残留重复通知或永久 loading。

### E-08 空草稿与首条消息会话边界

- 优先级：P1
- 前置：首次打开 Agentic Chat，历史中没有当前空会话。
- 操作：观察初始历史，连续新建但不发送草稿，再发送第一条有效内容；另行注入启动预建会话失败后重试首条发送。
- 预期：
  - 未使用的启动会话和未发送草稿不出现在可见历史或任务列表中，不产生多个“New Session”空记录。
  - 第一条有效内容复用可用的启动会话；若启动预建失败，则在首发时惰性创建并正常发送。
  - 任务或历史记录只在用户内容被接受后出现，首条消息不会创建两个会话或两条用户记录。
  - 新建空草稿不会改变已有 Active Session 的持久恢复目标。

## F. 基础组件与终端回归

### F-01 项目重命名弹窗样式与交互回归

- 优先级：P1
- 前置：从 Agentic 项目管理菜单打开重命名弹窗。
- 操作：检查居中、遮罩、外层自定义样式、保存和取消，再重复打开关闭。
- 预期：
  - 弹窗保持居中和既有 wrapper 样式，遮罩及按钮交互正常。
  - 重复打开关闭不出现 React 18 旧渲染 API 警告、重复弹窗或残留遮罩。

### F-02 通知显示、关闭与销毁回归

- 优先级：P1
- 前置：触发任务历史不可用、创建失败或容量已满等非阻塞通知。
- 操作：连续触发不同位置/类型通知，关闭单条，再执行全部销毁。
- 预期：
  - 通知在正确容器和位置显示，图标、关闭按钮和自动关闭行为正常。
  - 相同实例可继续追加通知；关闭或销毁后 DOM 容器被清理，不重复显示、不残留空节点。
  - 控制台不出现 `ReactDOM.render` 已废弃警告。

### F-03 终端视图重复挂载生命周期

- 优先级：P1
- 前置：打开终端并让其获得焦点。
- 操作：切换布局或反复显示/隐藏终端，使终端视图卸载并重新挂载；随后聚焦、失焦和打开右键菜单。
- 预期：
  - 每次挂载只保留一个有效终端上下文服务，旧上下文被释放。
  - `terminalFocus` 和终端初始化上下文状态与当前视图一致；聚焦、快捷键和右键菜单继续正常。
  - 视图尚未挂载或正在切换时不会因空上下文抛错。
