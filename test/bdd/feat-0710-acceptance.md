# feat/0710 对比 main 的行为验收用例

## 对比基线

- 验收分支：`feat/0710`
- 对比分支：`main`
- Merge Base：`094b998ee11d130821ea25af4390e656e35ea425`
- 对比范围：`main...HEAD` 中的产品代码和测试代码；不包含本地未提交的文档与临时文件。
- 本清单用于人工验收。仓库内已有自动化场景仍以对应 `.scenario.md`、Jest 和 Playwright 用例为准。

## 主要行为变化

1. 编辑器新增固定标签能力，包括固定区域、关闭保护、滚动可达性、持久化和 VS Code Tab API 状态同步。
2. Agentic 布局新增常驻任务工作台，包括项目管理、任务创建、跨项目会话激活、项目名称、归档和尺寸调整。
3. ACP Chat 新增排队任务，包括严格 FIFO、行内编辑、暂停/继续、立即发送、失败恢复和会话隔离。
4. ACP 输入补充快捷键、焦点、粘贴、图片和展开行为；工具调用卡片补充键盘和无障碍交互。

## 验收环境与数据

- 使用一次性工作区，至少包含 `editor.js`、`editor2.js`、`editor3.js`。
- 默认布局用例使用 `default` profile；Agentic 任务和排队任务使用 `interactive` profile。
- Agentic 用例建议使用 `test/bdd/fixtures/acp-agent/mock-acp-agent.mjs` 的确定性 fixture，避免依赖真实模型输出。
- 跨项目用例准备三个目录：当前项目、另一个存在的项目、一个已删除或不可访问的项目。
- 验收期间不要断言 Agent 回复正文、思考内容、工具参数或精确流式时序。
- 启动服务前可检查端口：

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN || true
lsof -nP -iTCP:8000 -sTCP:LISTEN || true
```

先执行全部 P0 用例；P0 通过后，再执行布局、持久化、异常恢复和无障碍相关的 P1 用例。

## A. 编辑器固定标签

### A-01 固定非当前标签不切换编辑器

- 优先级：P0
- 前置：依次打开 `editor.js`、`editor2.js`，当前标签为 `editor2.js`。
- 操作：右键非当前的 `editor.js`，选择“固定标签”。
- 预期：
  - `editor.js` 移到固定区域并显示“取消固定”控件。
  - 当前编辑器仍是 `editor2.js`，编辑器焦点不被抢走。
  - `editor.js` 不再是预览标签。
- 自动化参考：`test/bdd/editor-pinned-tabs.scenario.md` Part A。

### A-02 固定标签的关闭保护

- 优先级：P0
- 前置：`editor.js` 已固定，另有至少一个普通标签。
- 操作：依次尝试关闭按钮、中键点击、`Cmd/Ctrl+W`、“关闭其他”、“关闭右侧”、“关闭全部”和“关闭已保存”。
- 预期：
  - 固定标签不显示普通关闭按钮，中键不能关闭。
  - 批量关闭操作跳过所有固定标签。
  - 当 `Cmd/Ctrl+W` 作用于固定标签时，切换到第一个普通标签而不关闭固定标签。
  - 若组内只有固定标签，`Cmd/Ctrl+W` 不执行关闭，也不把焦点切到其他编辑器组。

### A-03 显式关闭与重新打开

- 优先级：P0
- 前置：`editor.js` 已固定并已保存。
- 操作：从标签右键菜单选择“关闭”，随后执行“重新打开已关闭的编辑器”。
- 预期：
  - 显式“关闭”可以关闭固定标签。
  - 重新打开后，`editor.js` 是普通标签，不自动恢复固定状态或原固定位置。

### A-04 取消固定快捷键与键盘按钮

- 优先级：P0
- 前置：`editor.js` 已固定。
- 操作：分别使用“取消固定”按钮的 Enter、Space，以及 `Cmd/Ctrl+K` 后按 `Shift+Enter`。
- 预期：
  - 三种方式都能取消固定。
  - 操作按钮时不会触发父标签切换。
  - 取消固定后显示普通关闭按钮，且不会恢复为预览标签。

### A-05 固定标签的脏状态

- 优先级：P0
- 前置：`editor.js` 已固定。
- 操作：观察已保存状态，然后编辑文件但不保存。
- 预期：
  - 已保存时不显示虚假的脏状态圆点。
  - 未保存时同时显示脏状态和“取消固定”控件。
  - 保存后脏状态消失，固定状态保持不变。

### A-06 非换行模式下固定区域保持可见

- 优先级：P1
- 前置：`editor.wrapTab=false`，固定至少两个标签，再打开多个普通标签。
- 操作：水平滚动普通标签区域到最右侧。
- 预期：
  - 固定区域保持在左侧，不随普通标签一起滚走。
  - 编辑器操作区和右侧扩展内容不被覆盖。
  - 当前普通标签在固定区域右侧仍有可见像素并可操作。

### A-07 固定标签过宽时仍可到达当前标签

- 优先级：P1
- 前置：固定足够多的标签，使固定区域宽度超过可用宽度。
- 操作：通过资源树、快捷键或其他非直接点击方式激活最右侧固定标签。
- 预期：
  - 固定区域形成独立的横向滚动视口。
  - 当前固定标签会滚动到固定区域和外层视口的可见范围内。
  - 不会把普通标签区永久挤到完全不可用。

### A-08 标签换行模式与动态切换

- 优先级：P1
- 前置：固定两个标签，保留一个普通标签。
- 操作：先设置 `editor.wrapTab=true`，再运行时切回 `false`。
- 预期：
  - 换行模式下只有一个自然换行的标签序列，顺序为固定标签在前、普通标签在后。
  - 不出现单独的固定标签行或固定区域横向滚动条。
  - 切回非换行模式后，固定区域宽度和当前标签可达性重新计算正确。

### A-09 固定状态持久化

- 优先级：P0
- 前置：固定 `editor.js`，等待编辑器状态保存。
- 操作：刷新页面或重启 IDE。
- 预期：
  - `editor.js` 恢复为固定标签。
  - 缺失、无法恢复或不支持恢复的资源不会导致后续普通标签被误固定。
  - 同一个 URI 在不同编辑器组中的固定状态相互独立。

### A-10 拖拽、拆分与跨组行为

- 优先级：P1
- 前置：准备两个编辑器组，并包含固定、普通和预览标签。
- 操作：
  1. 将普通标签拖入固定区域。
  2. 将固定标签拖到普通区域。
  3. 将固定标签拆分到新组。
  4. 将固定标签拖入空的新组。
- 预期：
  - 拖入固定区域后变为固定；拖出后变为普通。
  - 预览标签拖入固定区域时先转为正式标签。
  - 拆分后的新组副本保持固定，源组固定状态不变。
  - 拖入空组时保留源标签的固定状态。

### A-11 扩展 Tab API 同步

- 优先级：P1
- 前置：安装或运行能够读取 VS Code Tab API 的测试扩展。
- 操作：固定、取消固定并移动标签。
- 预期：
  - 扩展侧 `Tab.isPinned` 与界面状态一致。
  - 固定或取消固定导致排序变化时，扩展侧顺序同步更新。
  - 仅固定边界变化但索引不变时，扩展仍收到状态更新。

## B. Agentic 任务工作台

### B-01 Agentic 工作台基本布局

- 优先级：P0
- 前置：以 Agentic 布局打开 IDE。
- 操作：显示 AI Chat。
- 预期：
  - 任务列表、主对话区、资源管理器和编辑器同时可见。
  - 任务列表位于 ACP Chat 槽位内部，不覆盖编辑器或资源管理器。
  - 行样式接近 OpenSumi 原生树/列表，不出现卡片式任务行、渐变栏或永久文字操作按钮。
- 自动化参考：`tools/playwright/src/tests/acp-chat-agentic-task-workbench.test.ts`。

### B-02 任务列表尺寸调整

- 优先级：P1
- 前置：任务列表可见。
- 操作：分别用鼠标拖拽和键盘调整宽度，再缩窄整个 Chat 槽位。
- 预期：
  - 默认宽度约为 244px，最小宽度为 208px。
  - 最大宽度为 `min(480px, Chat 槽位宽度 - 360px)`。
  - 主对话区始终保留至少 360px。
  - Chat 槽位变窄后，之前保存的过宽值会被安全收敛。
  - 指针离开窄调整手柄后，拖拽仍连续生效；焦点样式清晰。

### B-03 项目显示名称与完整路径

- 优先级：P0
- 前置：准备无自定义名称的项目，以及末级目录同名的两个可用项目。
- 操作：观察项目列表、搜索前后标签和悬停提示。
- 预期：
  - 默认显示规范化 cwd 的最后一段；文件系统根目录显示 `/`。
  - 同名项目使用最短父路径后缀消歧。
  - 搜索任务不会改变项目标签或项目/任务顺序。
  - 悬停项目名称可看到完整 cwd。

### B-04 重命名项目

- 优先级：P1
- 前置：存在可用的活动项目。
- 操作：从项目管理菜单打开重命名弹窗，分别执行保存、取消、清空名称。
- 预期：
  - 输入框自动聚焦；未命名项目以默认名称作为占位符，并单独展示完整 cwd。
  - 保存会去除首尾空格并持久化非空名称。
  - 取消不修改名称。
  - 清空后恢复派生默认名称。
  - 重命名不改变项目身份、任务归属、ACP 会话或排序；归档项目不可重命名。

### B-05 添加项目但不切换 IDE 工作区

- 优先级：P0
- 前置：当前编辑器和资源树已打开一个工作区。
- 操作：点击任务列表标题栏的“添加项目”，选择另一个目录。
- 预期：
  - 使用现有目录选择器。
  - 新目录作为空项目组出现，但浏览器 URL、资源树和编辑器工作区不变化。
  - 重复选择已有目录只重新校验可用性，不创建重复项目。
  - 标题栏“添加项目”只添加项目，不创建任务。

### B-06 项目组内创建任务

- 优先级：P0
- 前置：项目组可见且至少配置一个 ACP Agent。
- 操作：点击项目组标题中的图标 `+`，输入第一条内容并发送。
- 预期：
  - 项目组只有一个图标式新建任务按钮，不显示“New Task”文字或 Agent 下拉箭头。
  - 草稿使用该项目记忆的 Agent 和该项目 cwd。
  - 发送第一条内容前不创建持久任务行；首次发送成功后才出现任务行。
  - 不切换 IDE 工作区、不刷新页面，也不触发脏编辑器保存/丢弃提示。

### B-07 对话标题栏创建任务与 Agent 选择

- 优先级：P0
- 前置：配置 `Agent A`、`Agent B`。
- 操作：点击对话标题栏 `+`，选择 Agent 后发送首条内容。
- 预期：
  - 点击才打开锚定菜单，悬停不会打开；菜单不出现“选择项目”。
  - 菜单包含 Agent 列表、下一任务将使用的 Agent 勾选状态和“Agent 配置”。
  - 已选中持久任务时，新草稿沿用该任务所属项目；否则使用当前 IDE 工作区。
  - Agent 选择只更新目标项目的 Agent 记忆，不修改用户级默认 Agent。
  - 无可用 Agent 时标题栏 `+` 仍可打开“Agent 配置”，项目组 `+` 则禁用并给出原因。

### B-08 当前项目任务激活

- 优先级：P0
- 前置：当前项目有两个可恢复任务，其中一个带未读标记。
- 操作：点击非当前任务。
- 预期：
  - 对应 ACP 会话被恢复，选中态移动到目标任务。
  - 激活成功后才清除未读标记。
  - URL、IDE 工作区、资源树和编辑器状态不变化。

### B-09 跨项目任务原地激活

- 优先级：P0
- 前置：当前工作区有未保存编辑器；另一个项目有可恢复任务。
- 操作：点击另一个项目的任务。
- 预期：
  - 仅切换 ACP Active Session，不切换 IDE 工作区。
  - URL、资源树、编辑器内容和未保存状态保持不变。
  - 不显示保存/丢弃/取消工作区切换弹窗。
  - 标题栏显示“Agent 工作目录”及目标项目名称，悬停显示完整 cwd。
  - 激活成功后才清除目标任务未读标记。

### B-10 激活失败与快速连续选择

- 优先级：P0
- 前置：准备一个无法恢复的任务和两个可恢复任务。
- 操作：
  1. 先点击无法恢复的任务。
  2. 快速连续点击两个可恢复任务，并人为让前一次请求更晚返回。
- 预期：
  - 激活失败时保留原对话、原任务选中态和未读标记，不打开无绑定草稿。
  - 快速选择遵循“最后一次选择生效”，旧请求晚返回不能覆盖最新选择。

### B-11 不可用项目过滤

- 优先级：P0
- 前置：注册表保留一个 cwd 已不存在的项目及其任务。
- 操作：观察活动区、归档区、搜索结果和注意力计数。
- 预期：
  - 不可用项目及其任务默认全部隐藏。
  - 不贡献可见任务数或注意力计数。
  - 不显示项目组新建按钮，也不会调用工作区打开逻辑。
  - 数据仍保留在注册表中，目录恢复后可重新校验。

### B-12 搜索、状态与注意力

- 优先级：P1
- 前置：存在运行中、就绪、停止、错误、需要权限和需要输入的任务。
- 操作：按任务标题搜索并观察各任务行。
- 预期：
  - 只按不可变任务标题过滤，不搜索提示词或消息内容。
  - 搜索不改变项目和任务原始顺序。
  - 注意力状态优先于普通运行状态显示。
  - 任务行保持单行，完整标题仍可通过悬停或无障碍信息访问。

### B-13 归档与恢复

- 优先级：P0
- 前置：准备就绪、停止、错误和运行中任务。
- 操作：悬停或键盘聚焦任务行，执行归档；展开“已归档任务”并恢复。
- 预期：
  - 只有就绪、停止或错误任务可以归档；运行中任务不可归档。
  - 归档/恢复是图标操作，默认不长期显示文字按钮，但具有明确的无障碍名称。
  - 恢复后任务回到原项目，标题、状态、项目引用和会话身份不丢失。

### B-14 Agentic 与 Classic 边界

- 优先级：P1
- 前置：Agentic 任务列表已有任务和归档状态。
- 操作：Agentic -> Classic -> Agentic。
- 预期：
  - Classic 保留原有 ACP 历史按钮/弹层行为，不显示 Agentic 任务工作台。
  - 回到 Agentic 后任务列表、标题栏新建任务入口和原任务身份恢复。
  - 不改变 IDE 通用布局生命周期。

## C. ACP 排队任务与输入行为

### C-01 生成期间提交形成严格 FIFO

- 优先级：P0
- 前置：Active Session 正在生成。
- 操作：依次提交 `fifo-1`、`fifo-2`、`fifo-3`。
- 预期：
  - 三条内容按提交顺序进入排队列表，计数正确，首次入队自动展开。
  - 当前生成完成后，只取队首开始发送，每条恰好发送一次。
  - 自动推进顺序严格为 `fifo-1`、`fifo-2`、`fifo-3`。
  - 入队、展开、收起和自动推进都不抢走主输入框焦点。
- 自动化参考：`test/bdd/acp-chat-agentic-queued-turns.scenario.md`。

### C-02 编辑非队首任务不改变顺序

- 优先级：P0
- 前置：队列为 `fifo-1`、`fifo-2`、`fifo-3`。
- 操作：编辑第二条为 `fifo-2-edited` 并保存。
- 预期：
  - 编辑器获得焦点。
  - 条目 ID、索引和 FIFO 位置保持不变。
  - 第一条仍可正常先发送，编辑第二条不阻塞队首。
  - 保存完成后焦点回到主输入框。

### C-03 编辑队首时阻塞自动推进

- 优先级：P0
- 前置：队首正在行内编辑，当前生成即将完成。
- 操作：分别验证保存、取消和删除队首编辑。
- 预期：
  - 未处理编辑前，队首不会自动发送。
  - 保存后发送修改后的队首；取消后发送原内容；删除后发送下一条。
  - 同时只能编辑一条；点击其他条目的编辑不会丢弃当前未保存内容，而是聚焦当前编辑器。
  - 有未保存行内编辑时不能收起队列。

### C-04 手动停止后暂停并继续队列

- 优先级：P0
- 前置：使用 `long-stream`，当前生成中，队列包含 `resume-head`、`resume-tail`。
- 操作：点击“停止”，等待取消完成，再点击“继续队列”。
- 预期：
  - 点击停止后队列立即进入“已暂停/已停止”，不会自动推进。
  - 两条排队任务顺序不变，当前已开始的任务不重新入队。
  - “继续队列”只启动 `resume-head` 一次，并保留 `resume-tail` 为下一条。

### C-05 立即发送等待取消确认

- 优先级：P0
- 前置：当前生成中，队列为 `immediate-first`、`immediate-selected`、`immediate-last`。
- 操作：对第二条选择“立即发送”。
- 预期：
  - 系统先取消当前生成；取消确认前不会发送目标任务。
  - 等待期间相关立即发送动作禁用，避免重复取消或重复发送。
  - 取消确认后，`immediate-selected` 只发送一次。
  - 剩余顺序为 `immediate-first`、`immediate-last`，后续继续按 FIFO。
  - 焦点只在立即发送完成后回到主输入框。

### C-06 立即发送取消或启动失败恢复

- 优先级：P0
- 前置：分别注入取消失败和目标启动失败。
- 操作：选择队列中的非队首任务立即发送。
- 预期：
  - 取消失败时目标任务恢复到队首，外部生成真实状态不被伪造，队列暂停。
  - 取消成功但目标启动失败时，目标同样恢复到队首并暂停。
  - 目标内容、ID、编辑状态和剩余 FIFO 不丢失、不重复。

### C-07 普通启动失败可恢复

- 优先级：P0
- 前置：使用一次性 `acpBddQueuedTurnStartFailure=reject-once` fixture。
- 操作：提交 `start-failure-head`，失败后点击“继续队列”。
- 预期：
  - 首次失败不创建用户消息行、加载状态或停止按钮。
  - 原任务恢复为队首，显示“已暂停/启动失败”。
  - 再次继续无需刷新，发送同一条任务且没有重复行或顺序变化。

### C-08 Agent 出错和取消失败后的显式恢复

- 优先级：P1
- 前置：分别注入 Agent 已开始后报错、停止请求失败。
- 操作：观察队列并使用继续、编辑、删除、新普通提交或立即发送恢复。
- 预期：
  - 已开始后报错的活动任务不重新入队，剩余任务保留并暂停。
  - 停止失败时保持暂停，不自动重试，避免重复外部操作。
  - 错误以非阻塞方式显示规范化原因，不弹出阻塞模态框。

### C-09 Active Session 切换隔离

- 优先级：P0
- 前置：Session A 正在生成并有排队任务和行内编辑；Session B 可选。
- 操作：切换到 Session B，再切回 Session A。
- 预期：
  - Session B 不显示 Session A 的队列、编辑器或加载状态。
  - Session A 的旧完成回调不能在 Session B 启动旧任务，也不能抢焦点。
  - 主草稿不被意外清空；输入展开状态退出但不发生异常焦点跳转。
  - 切回 Session A 不恢复已经清除的旧队列。

### C-10 清空、删除和取回最后一条

- 优先级：P0
- 前置：队列包含多条内容，其中一条正在编辑。
- 操作：分别执行删除、全部清除，以及主输入为空时按 `ArrowUp`。
- 预期：
  - 删除只移除目标任务；删除队首后下一条可以继续处理。
  - 全部清除会清空队列、编辑状态、暂停状态和一次性快速发送状态，但不会伪造当前已确认活动发送的结束。
  - `ArrowUp` 只取回队尾一条，恢复可支持的文本、Mention、图片和命令字段，光标位于末尾并聚焦主输入。
  - 队列为空时，`ArrowUp` 回退到原有输入历史行为。

### C-11 主输入快捷键和 IME

- 优先级：P0
- 前置：主输入获得焦点。
- 操作：验证 Enter、Shift+Enter、`Cmd/Ctrl+Shift+Enter`、Escape 和中文输入法组合态。
- 预期：
  - 空闲时 Enter 立即发送；生成中 Enter 入队。
  - Shift+Enter 插入换行。
  - `Cmd/Ctrl+Shift+Enter` 执行立即发送。
  - Escape 优先关闭 Mention、Slash 等临时浮层；无浮层时才停止生成并暂停队列。
  - 输入法组合期间上述提交快捷键不会误发送。

### C-12 一次性空 Enter 快速发送

- 优先级：P1
- 前置：主输入刚把一条任务加入队列，输入框为空。
- 操作：立即再次按 Enter；然后修改主草稿后重复尝试。
- 预期：
  - 第一次空 Enter 只对队首执行一次“立即发送”。
  - 使用后状态失效，不能重复触发。
  - 用户真实修改草稿、切换会话、清空队列或其他影响队首的动作都会使该状态失效。

### C-13 行内编辑快捷键

- 优先级：P1
- 前置：打开某条排队任务的行内编辑器。
- 操作：验证 Enter、Shift+Enter、`Cmd/Ctrl+Shift+Enter`、Escape。
- 预期：
  - Enter 原位保存；Shift+Enter 插入换行。
  - `Cmd/Ctrl+Shift+Enter` 保存并立即发送同一条任务。
  - Escape 丢弃本次编辑副本并保留原任务。
  - 保存、取消、删除和立即发送完成后焦点回主输入框。

### C-14 文本、图片和混合粘贴

- 优先级：P1
- 前置：分别聚焦主输入和行内队列编辑器。
- 操作：粘贴纯文本、HTML 外观的 `text/plain`、单张图片、文本与多张图片混合内容，并注入一张图片上传失败。
- 预期：
  - 文本插入到粘贴发生时的光标位置，不被当作 HTML 执行。
  - 图片附加到当前编辑的同一草稿，不迁移到另一个输入框。
  - 混合粘贴保留文本和上传成功的图片，只报告失败图片数量。
  - 异步上传完成前后，文本插入位置稳定；原编辑器卸载后不会把延迟结果写入新编辑器。

### C-15 输入展开状态保持

- 优先级：P1
- 前置：输入中包含文本、Mention、图片、选区和光标位置。
- 操作：点击展开按钮，并使用 `Shift+Alt/Option+Escape` 来回切换。
- 预期：
  - 按钮和快捷键使用同一命令语义。
  - 展开/收起不重建草稿，文本、Mention、图片、光标、选区和焦点全部保留。
  - Active Session 切换时退出展开状态。

## D. 工具调用卡片无障碍行为

### D-01 工具卡片键盘展开与收起

- 优先级：P1
- 前置：对话中存在工具调用卡片。
- 操作：聚焦卡片标题，分别按 Enter 和 Space。
- 预期：
  - 标题是可聚焦的 disclosure button，并暴露正确的展开状态。
  - Enter 和 Space 都能切换展开/收起；Space 不滚动页面。
  - 按键长按产生的 repeat 事件不会重复切换。
  - 操作后焦点仍在卡片标题。

### D-02 收起内容不可聚焦且不进入无障碍树

- 优先级：P1
- 前置：工具卡片内容中包含按钮、链接或其他可聚焦元素。
- 操作：收起卡片后使用 Tab 导航和辅助技术检查。
- 预期：
  - 收起内容仍可保持挂载，但其后代不能获得焦点，也不暴露到无障碍树。
  - 再次展开后，后代恢复正常交互。
  - MCP 工具保留 MCP 前缀；非 MCP 工具使用中性前缀。
