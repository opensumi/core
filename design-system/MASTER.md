# OpenSumi Design System — Master

状态：Baseline 1.0

适用范围：OpenSumi Web IDE、Electron IDE、内置工作台视图与 OpenSumi 自有功能界面。

## 1. 设计目标

OpenSumi 是长时间使用、信息密度高、以键盘和编辑器为中心的开发者工具。设计应帮助用户保持上下文、快速定位信息并安全执行操作。

### 核心原则

1. **工作台优先**：新功能必须融入现有编辑器、侧边栏、面板、工具栏、Tab 和弹层体系。
2. **内容优先**：界面 chrome 保持克制，让代码、文件、终端、日志和任务状态成为视觉主体。
3. **上下文连续**：切换视图、打开弹层或执行异步操作时，保留选择、滚动、焦点和返回路径。
4. **高密度但不拥挤**：使用紧凑尺寸承载专业工作流，同时通过层级、分组和留白避免视觉噪音。
5. **键盘与鼠标平等**：任何核心操作都不能只依赖 hover、右键或拖拽。
6. **主题原生**：亮色、暗色和高对比度主题是同一功能的并列形态，不是后续适配项。
7. **状态真实可见**：加载、成功、失败、禁用、选中和只读必须明确，不能依赖猜测或仅依赖颜色。

## 2. 视觉方向

### 风格

- 专业、克制、技术感、低装饰。
- 允许局部强调，但一个区域只保留一个主要视觉动作。
- 避免大面积渐变、装饰性玻璃效果、强烈拟物和与功能无关的连续动画。
- 避免为单一功能创建独立品牌化视觉语言；优先继承工作台主题。

### 信息层级

层级主要通过以下手段表达，优先级从高到低：

1. 区域位置与布局关系。
2. 字号、字重与间距。
3. 前景与背景对比度。
4. 边框、分隔线与表面层级。
5. 强调色。

不得只依赖颜色区分错误、选中、修改、删除或运行状态。

## 3. 布局与密度

### 工作台区域

优先复用现有区域：

- Activity Bar：一级工作区入口。
- Side Bar：资源树、搜索、源代码管理等持续性导航与上下文。
- Editor Group：主要内容和可持久化编辑对象。
- Panel：终端、输出、问题和调试等辅助工作区。
- Status Bar：持续状态和低优先级快捷入口。
- Modal、Popover、Quick Input：临时任务和短流程。

不要在功能包内部复制一套侧边栏、Tab 系统或编辑器布局。

### 密度基线

OpenSumi 采用桌面 IDE 紧凑密度：

| 类型                         |                         基线 |
| ---------------------------- | ---------------------------: |
| 正文字号                     |                         13px |
| 紧凑标签与控件文字           |                         12px |
| 默认按钮、输入框、选择器高度 |                         28px |
| 大号控件高度                 |                         32px |
| 小号控件高度                 |       22px，仅限次要紧凑区域 |
| 基础 UI 间距                 |                          6px |
| 常用间距序列                 | 2、4、6、8、12、16、24、32px |
| 默认圆角                     |                        2–4px |

22px 控件不得用于关键操作、复杂表单或需要清晰触控目标的界面。图标按钮的视觉图标可以较小，但可交互区域应优先达到 28×28px；低于 24×24px 时必须有足够间距、键盘替代和清晰 tooltip。

### 自适应

- 先保证工作台可缩放和分栏可收缩，再考虑固定宽度。
- 使用 `min-width: 0`、弹性布局和文本截断策略防止横向溢出。
- 固定工具栏、底栏和浮层不得遮挡滚动内容。
- 窄宽度下优先保留主要操作，将次要操作放入 overflow menu。
- 文本被截断时，应通过 tooltip、可展开内容或详情视图提供完整信息。

## 4. 色彩与主题

- 功能样式必须使用主题 CSS variables，不在 feature Less/TSX 中写主题相关 hex、rgb 或固定黑白值。
- 颜色意图应优先复用 `foreground`、`descriptionForeground`、`focusBorder`、`editor.*`、`list.*`、`input.*`、`button.*` 和 `kt.*` token。
- OpenSumi 自有组件可使用 `kt.*` token；通用工作台语义优先使用 VS Code 兼容 token。
- `design.*` token 仅用于其既有设计场景或明确共享的新场景，不能作为任意功能的通用颜色桶。
- 新颜色必须同时检查 dark、light、hcDark、hcLight。高对比度模式可以继承已有语义色，但必须保持边界、焦点和状态可辨识。
- 普通文本与背景对比度目标为 WCAG AA 4.5:1；大文字和非文本 UI 边界至少 3:1。

完整映射见 [TOKENS.md](./TOKENS.md)。

## 5. 字体与文本

### 字体

- UI 使用系统字体栈，避免为工作台引入阻塞渲染的网络字体。
- 代码、命令、标识符和等宽数据使用现有 code font 配置。
- 数字列、计时器和频繁变化的数值优先使用 tabular figures，避免宽度跳动。

### 字阶

| 角色               | 建议字号 |    字重 |    行高 |
| ------------------ | -------: | ------: | ------: |
| 辅助标签、徽标     |  11–12px | 400–500 | 16–18px |
| 紧凑控件           |     12px | 400–500 | 18–20px |
| 正文、列表、树节点 |     13px |     400 |    20px |
| 强调正文、分组标题 |     14px |     500 | 20–22px |
| 弹窗或页面标题     |     16px | 500–600 | 22–24px |
| 空状态主标题       |  20–24px | 500–600 | 28–32px |

正文不应小于 12px。不要使用全大写长文本；命令、快捷键和技术标识符除外。

### 文案

- 按钮使用明确动词，如“保存”“重试”“停止任务”，避免模糊的“确定”。
- 错误信息说明发生了什么、可能原因和恢复操作。
- 危险操作使用具体对象名称，例如“删除工作区配置”，并提供取消或撤销路径。
- tooltip 用于解释图标和补充快捷键，不应用来承载完成任务所必需的信息。

## 6. 图标

- 优先使用 OpenSumi Icon、Codicons 和现有 Product Icon Theme。
- 同一层级保持一致的描边、填充方式和视觉尺寸。
- 不使用 emoji 作为导航、状态或结构性图标。
- 图标颜色继承当前文本或使用主题 token，避免在 SVG/字体图标中写固定颜色。
- 纯图标按钮必须有可访问名称和 tooltip；tooltip 可附带快捷键。
- 状态不能只用图标表达，关键状态同时提供文本或可访问描述。

## 7. 交互状态

所有交互组件至少覆盖：

1. default
2. hover
3. active/pressed
4. focus-visible
5. disabled
6. loading（存在异步动作时）
7. error/invalid（存在校验时）
8. selected/expanded（存在选择或展开时）

状态优先级：disabled → loading → active → focus-visible → hover → default。

- hover 不能是唯一入口。
- `focus-visible` 必须清晰可见，不得只写 `outline: none`。
- disabled 必须使用原生 `disabled` 或正确的 `aria-disabled`，不能只降低透明度。
- loading 状态应阻止重复提交，并在操作超过约 300ms 时提供反馈。
- read-only 与 disabled 是不同状态：只读内容仍可聚焦、选择和复制。

## 8. 动效

动效只用于解释状态变化和空间关系。

| 类型                    |      时长 |
| ----------------------- | --------: |
| hover、颜色和透明度变化 | 100–150ms |
| 展开、Popover、轻量过渡 | 150–200ms |
| Modal、面板和复杂过渡   | 200–300ms |

- 进入使用 ease-out，退出使用更短的 ease-in。
- 优先动画 `transform` 和 `opacity`，避免动画 width、height、top、left 导致布局抖动。
- 禁止因动画阻塞输入或导航。
- 支持 `prefers-reduced-motion: reduce`；降低或关闭非必要移动、缩放和连续动画。
- 加载旋转可以持续，但装饰性图标不得无限动画。

## 9. 键盘与无障碍

- Tab 顺序与视觉顺序一致。
- 自定义树、列表、菜单、Tab 和组合框应遵循对应 ARIA pattern，不用无语义 `div` 模拟按钮。
- Modal 打开后将焦点移入，关闭后返回触发元素；Esc 可退出非强制流程。
- 菜单、快速选择和树支持方向键；Enter/Space 执行，Esc 返回。
- 拖拽、右键和 hover 操作必须有键盘或显式控件替代。
- 状态消息使用合适的 `aria-live`，不得无故抢夺焦点。
- 错误字段使用 `aria-invalid` 和 `aria-describedby`，错误信息靠近对应字段。
- 选中、展开、禁用、忙碌状态必须通过语义属性传达。

## 10. 反馈与异步操作

- 低于 300ms 的短操作通常无需全局 loading。
- 300ms–1s 使用局部 spinner、按钮 loading 或轻量占位。
- 超过 1s 的内容加载优先使用保留布局的 skeleton 或进度信息。
- 可取消任务提供“停止/取消”，并区分“正在停止”和“已停止”。
- 失败状态必须包含恢复路径：重试、修改配置、查看日志或打开帮助。
- 空状态说明为何为空，并给出下一步；不要只显示空白区域。
- Toast 适合短暂结果，不适合必须处理的错误或复杂说明。

## 11. 组件使用原则

- 优先复用 `@opensumi/ide-components`、工作台菜单、Quick Input、Dialog 和 Toolbar。
- 只有在现有组件无法表达共享需求时才新增组件。
- 功能私有组件留在功能包；跨包复用且不依赖 runtime 的纯组件才进入 `packages/components`。
- 组件不得自行创建与全局主题、z-index 或焦点管理平行的机制。

组件详细规范见 [COMPONENTS.md](./COMPONENTS.md)。

## 12. 禁止模式

- 在 feature 样式中硬编码主题颜色。
- 为局部功能复制主布局、Tab、菜单或弹层系统。
- 使用 placeholder 代替表单 label。
- 仅靠红/绿或透明度表达状态。
- 移除焦点轮廓但不提供替代。
- 点击后无即时反馈，或异步操作允许重复触发。
- 使用随机 z-index 解决遮挡问题。
- 用大面积动画、缩放或布局位移制造“高级感”。
- 在同一层级混用多套图标风格。

## 13. UI 完成定义

UI 变更只有在以下条件满足后才算完成：

- 复用了正确的工作台区域和组件。
- 没有新增主题相关硬编码颜色。
- dark、light 和相关高对比度行为已检查。
- hover、active、focus-visible、disabled、loading/error 等适用状态齐全。
- 核心流程可通过键盘完成，焦点进入与返回正确。
- 文本截断、窄宽度和滚动区域行为明确。
- 异步操作有反馈、取消或恢复路径。
- 运行时布局变更已在实际 IDE 或 Playwright 中验证。
