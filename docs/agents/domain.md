# Domain Docs

This repository uses a multi-context domain-document layout.

## Consumer rules

- Read `CONTEXT-MAP.md` first and follow it to the context relevant to the task.
- Read the relevant `CONTEXT.md` files and use their canonical terminology.
- Read applicable decisions under `docs/adr/` before changing architecture or behavior.
- If a proposal conflicts with an accepted ADR, surface the conflict explicitly rather than silently overriding it.
- Missing context-specific documentation is not a blocker; proceed with code evidence and update domain documentation only when terminology or a durable decision is resolved.
